# Watercolor Study

A local webapp for studying watercolors by master painters: understanding how they are built (values, color) and helping replicate them with real pigments.

Hobby project in applied computer vision and color science. Published on GitHub.

---

## How this repo works

- **The human (Daniel) decides** the architecture, data, algorithms and image transformations.
- **The code agent implements** decisions already made. It does not make architecture, algorithm or data-schema decisions on its own. If something is not specified, **ask before implementing**.
- Every change is verified with deterministic checks (pytest or a Python script), never by assuming it "works".
- Work proceeds step by step: explain the reasoning first, then execute.

### Environment

- **Native Windows 11** (no WSL2). All commands must be PowerShell or Python.
- No `grep`, `sed`, `awk`, `ls -la` or other Unix-only tooling.
- Python 3.13 in a local `venv` (`.venv`).
- No GPU. Nothing in the MVP may require one.

## MVP scope

Two modules only. Do little, but do it well.

### Module A — Value study (notan)

1. Convert the image to CIELAB and take **L\*** (perceptual lightness, range 0–100). Do not use RGB grayscale.
2. Posterize L\* into 3, 4 or 5 levels (user-selectable).
3. Show the L\* histogram of the artwork.

### Module B — Color → pigment recipe

1. The user selects an area of the artwork with the cursor; the area is averaged (not a single pixel, because of paper texture).
2. The color is reported in HEX and L\*a\*b\*.
3. Given a user-defined pigment palette, find the 3 best mixes (2–3 pigments, proportion and dilution).
4. Each recipe is reported with its **ΔE CIEDE2000** against the target color. No "probability" is reported.

Mixing uses Kubelka-Munk via `pymixbox`. License is CC BY-NC: valid for non-commercial use only.

### Out of MVP (v2 onwards)

Composition analysis, hard/soft edges, reserved whites, segmentation, cross-artist comparison.

## Color pipeline principles

Two **separate** stages, each testable on its own:

1. **Photo → true color of the artwork** (color constancy): illuminant and white-balance correction, using unpainted paper as the white reference. *Not in the MVP*; the MVP uses images as-is, but the architecture must leave room for this stage.
2. **True color → pigment recipe** (pigment physics, Kubelka-Munk).

Technical rules the code must follow:

- OpenCV loads images as **BGR**, not RGB. Convert explicitly.
- Color averages are computed in **linear space** or in Lab, never on gamma-encoded sRGB values.
- Use Lab on its real scale (L\* 0–100), not OpenCV's 0–255 scale for 8-bit images.
- Reference illuminant: **D65**, unless explicitly decided otherwise.

## Data

No database in the MVP: two CSV files and an image folder.

- **5 artists, 5 works each (25 watercolors).**
- **Public domain** works only, obtained from open museum APIs (Art Institute of Chicago, Metropolitan Museum).
- Initial artists: John Singer Sargent, Winslow Homer, J.M.W. Turner, Paul Cézanne, Thomas Moran.
- Images are **not versioned** in git: they are regenerated by the download script. The repo keeps the script and the CSVs.
- Images are resized to a maximum of **2000 px** on the long side when downloaded.

## Testing strategy

Each module is validated with controls, not visual inspection:

- **Positive control:** inputs with published results. E.g. the Sharma, Wu and Dalal (2005) test table for CIEDE2000.
- **Negative control:** a uniform gray image must yield a single value level and a single palette color.
- **Synthetic images:** code-generated gradients with known values (e.g. L\* from 0 to 100) to validate posterization.
- **Physical validation:** recipes are tested by painting the mixes on paper. No test replaces this step.
